# 招聘资料与本地知识库

## 当前收录范围

| 资料 | 数量 | 来源与用途 |
| --- | --- | --- |
| 编号 7424–7453 的招聘公告快照 | 30 份 | 根据招聘表格截图整理，用于公司、城市、招聘对象等信息查询 |
| 美的冰箱事业部、宝尊电商的 AI 实习说明 | 2 份 | 根据岗位截图整理，用于要求对比和实习条件筛选 |

这些文件保存在 `samples/` 中，是当前演示使用的输入资料。它们不代表完整招聘市场，也不等于 32 个独立岗位：一份公告可能包含多个岗位或多个城市。截图文字的整理可能存在遗漏，使用前应核对原始公告。

原在线表格包含 7000 多条记录，但当前项目没有全量导入它，也没有建立在线表格连接、自动采集或定时更新任务。岗位状态和时间均为资料中的历史记录，不代表今天仍在招聘。

## 文件怎样进入数据库

```text
samples/*.md → 网页批量上传 → 保存原文件至 data/docs/
                          ├─ 文本切片 → BGE 向量化 → Chroma
                          └─ 提取约定格式的字段 → SQLite
```

- **Chroma**：保存片段原文、向量及来源，用于语义检索问答；运行数据在 `data/chroma/`。
- **SQLite**：保存从 Markdown 提取的公司、岗位、城市、实习时长等字段，用于精确条件筛选；运行数据在 `data/jobs.sqlite3`。
- **GitHub 仓库**：保存代码与输入资料，不提交本机数据库、API 密钥或运行报告。

因此，把文件放进 `samples/` 不会自动入库。首次启动后，在页面点击上传，多选这 32 个 Markdown 文件，等待上传结果，再检查文档列表与问答来源。已有资料无需反复上传。

## 更新与核对

1. 修改本地资料后，以相同文件名重新上传，系统会更新对应文档索引及结构化记录。
2. 新资料沿用现有 Markdown 字段格式；TXT、可提取文字的 PDF 也支持语义问答，但不会自动形成同样的结构化筛选记录。
3. 未提供的薪资、住宿、实习时长等字段保持未知；不要根据公司常见待遇补写。
4. 截图中的“投递链接”若没有显示实际网址，只保留这一说明，不猜测链接。
5. 清空知识库会清空当前索引，保留上传原文件；重启不会自动重新入库，需要再次上传。

检索展示的相关度不是答案正确概率。演示时应展开来源核对答案；正式投递时，以公司官方岗位信息为准。
